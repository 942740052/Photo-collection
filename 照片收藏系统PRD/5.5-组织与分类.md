# 5.5 组织与分类

| 模块信息 | 内容 |
|---------|------|
| **模块编号** | 5.5 |
| **模块名称** | 组织与分类 |
| **优先级** | P0（核心功能） |
| **依赖模块** | 5.1（用户与账户管理 — 相册归属用户）、5.13（AI 引擎 — 智能分类由 AI 引擎提供）、5.9（媒体管理与生命周期 — 归档由生命周期模块管理） |

---

## 模块概述

本模块负责照片和视频的组织、分类和归档管理，包括相册管理、标签系统、收藏夹、照片堆叠、归档功能和文件夹视图。作为系统的"组织中枢"，本模块确保用户能高效地管理和查找自己的媒体资产，同时提供智能分类能力（依赖 AI 引擎）和灵活的归档机制。

---

## 子功能详细说明

### 5.5.1 相册管理

| 功能 | 描述 | 优先级 |
|------|------|:------:|
| 创建相册 | 创建新相册，设置名称、描述、封面 | P0 |
| 编辑相册 | 修改相册名称、描述、封面、排序 | P0 |
| 删除相册 | 删除相册（照片可选择保留或一并删除） | P0 |
| 相册类型 | 普通相册、智能相册（基于规则自动填充）、共享相册 | P1 |
| 相册嵌套 | 支持文件夹层级结构（最多 3 层） | P1 |
| 相册排序 | 按日期、名称、手动拖拽排序 | P0 |
| 相册封面 | 自动选取或手动设置相册封面 | P0 |
| 照片添加/移除 | 向相册添加或移除照片（不删除原始文件） | P0 |
| 相册复制 | 复制整个相册及其内容 | P2 |
| 相册统计 | 显示相册内照片数量、总大小、最后更新时间 | P1 |

**智能相册规则类型：**

| 规则类型 | 示例 | 说明 |
|----------|------|------|
| 按日期范围 | "2025 年所有照片" | 指定时间范围 |
| 按标签组合 | "包含'风景'和'日落'标签" | 多标签逻辑（AND/OR/NOT） |
| 按人物 | "包含'宝宝'的所有照片" | 依赖 AI 引擎的人物识别 |
| 按地点 | "在'北京'拍摄的照片" | 依赖 GPS 数据 |
| 按设备 | "用 iPhone 拍摄的照片" | 依赖 EXIF 中的设备信息 |
| 按评分 | "4 星及以上" | 依赖用户评分 |
| 按文件类型 | "仅 RAW 格式" | 依赖文件格式 |
| 组合规则 | "2025 年 + 北京 + 风景标签" | 支持复杂组合 |

**用户故事：**

> 作为标准用户，我希望创建一个智能相册，自动收集所有包含"宝宝"标签的照片，以便随时查看孩子的成长记录。

> 作为摄影爱好者，我希望按项目创建嵌套相册结构（如"2025/婚礼/预拍"），以便有序管理拍摄项目。

> 作为家庭用户，我希望将旅行照片组织到不同相册，每个相册设置封面，以便快速识别。

**验收标准：**

```gherkin
Scenario: 智能相册自动填充
  Given 用户创建了一个智能相册，规则为"标签包含'风景'"
  When 系统中有新照片被标记了"风景"标签
  Then 该照片自动出现在智能相册中
  And 智能相册的统计信息（照片数量）实时更新

Scenario: 相册嵌套
  Given 用户已创建相册"2025"
  When 用户在"2025"下创建子相册"旅行"
  Then 相册列表中显示层级结构
  And 用户可进入子相册查看内容
  And 用户可以拖拽调整相册层级

Scenario: 相册照片管理
  Given 用户在相册A中有 100 张照片
  When 用户将其中 20 张照片移动到相册B
  Then 相册A 中照片数量减少为 80
  And 相册B 中新增 20 张照片
  And 原始文件未被删除
```

### 5.5.2 标签系统

| 功能 | 描述 | 优先级 |
|------|------|:------:|
| 标签 CRUD | 创建、编辑、删除标签 | P0 |
| 层级标签 | 支持标签树/标签组（如"地点 > 中国 > 北京"） | P2 |
| 批量打标签 | 选中多张照片批量添加/移除标签 | P0 |
| 标签云展示 | 以标签云形式展示所有标签及其使用频率 | P1 |
| 标签合并 | 将多个相似标签合并为一个 | P1 |
| 标签颜色/图标 | 为标签设置自定义颜色或图标 | P2 |
| 标签使用统计 | 显示各标签的使用次数和趋势 | P2 |
| AI 自动标签 | AI 自动识别并建议标签（由 5.13 AI 引擎提供） | P1 |
| 标签搜索 | 支持按标签名搜索和筛选 | P0 |
| 标签快捷键 | 为常用标签设置快捷键（如按 T 打开标签面板） | P2 |

**用户故事：**

> 作为用户，我希望为照片批量添加标签，以便快速分类大量照片。

> 作为用户，我希望创建层级标签结构（如"地点 > 中国 > 北京"），以便按地理位置组织标签。

> 作为用户，我希望系统根据 AI 识别自动建议标签，我只需确认即可，节省手动打标签时间。

**验收标准：**

```gherkin
Scenario: 批量打标签
  Given 用户选中 50 张照片
  When 用户点击"添加标签"并选择"风景"和"日落"
  Then 所有 50 张照片都被添加这两个标签
  And 标签使用统计中"风景"和"日落"的计数各增加 50

Scenario: 标签合并
  Given 系统中存在相似标签"海滩"和"海边"
  When 管理员选择"海滩"和"海边"进行合并
  Then 两个标签合并为一个（如"海滩"）
  And 原有的"海滩"和"海边"标签被删除
  And 所有原来标记这两个标签的照片自动更新为合并后的标签

Scenario: AI 自动标签
  Given 系统中上传了一张包含海滩的照片
  When AI 引擎完成分析并返回"海滩"标签
  Then 该照片自动被标记"海滩"标签
  And 用户可在照片详情中看到该标签
  And 用户可以选择接受或移除该标签
```

### 5.5.3 收藏夹

| 功能 | 描述 | 优先级 |
|------|------|:------:|
| 收藏/取消收藏 | 一键收藏或取消收藏照片 | P0 |
| 收藏快速访问 | 在导航栏提供收藏夹快速入口 | P0 |
| 智能收藏 | 基于规则自动收藏（如"AI 评分高于阈值"） | P2 |
| 收藏夹分类 | 支持创建多个收藏夹/精选集 | P1 |
| 收藏夹排序 | 按收藏时间、名称、自定义排序 | P1 |
| 收藏夹共享 | 分享收藏夹给其他用户 | P2 |
| 收藏夹封面 | 为收藏夹设置封面图片 | P1 |

**用户故事：**

> 作为用户，我希望一键收藏喜欢的照片，以便快速访问精选内容。

> 作为用户，我希望创建多个收藏夹（如"旅行精选"、"家庭回忆"），以便分类管理收藏内容。

**验收标准：**

```gherkin
Scenario: 收藏照片
  Given 用户在浏览照片时看到一张喜欢的照片
  When 用户点击收藏按钮（心形图标）
  Then 该照片被添加到收藏夹
  And 收藏按钮变为已收藏状态
  And 用户可在导航栏的"收藏"入口快速查看所有收藏的照片

Scenario: 创建收藏夹
  Given 用户已收藏 100 张照片
  When 用户创建一个名为"旅行精选"的收藏夹
  And 将其中 20 张收藏的照片移动到该收藏夹
  Then "旅行精选"收藏夹包含 20 张照片
  And 总收藏夹仍显示 100 张照片（收藏夹是虚拟分组，不重复计数）
```

### 5.5.4 照片堆叠 Stacks

| 功能 | 描述 | 优先级 |
|------|------|:------:|
| 自动堆叠 | 自动将连拍、HDR 候选、相似场景的照片分组 | P1 |
| 手动堆叠 | 用户手动选择多张照片创建堆叠 | P1 |
| 堆叠展开/折叠 | 点击堆叠展开查看所有照片，折叠后只显示封面 | P1 |
| 堆叠封面 | 自动选择或手动设置堆叠封面 | P1 |
| 堆叠排序 | 堆叠内照片按拍摄时间、评分等排序 | P1 |
| 堆叠拆分 | 将堆叠拆分为独立照片 | P1 |
| 堆叠合并 | 将多张照片合并为一个堆叠 | P1 |

**堆叠触发条件：**

| 条件 | 说明 |
|------|------|
| 连拍检测 | 拍摄时间差 < 2 秒的照片 |
| HDR 候选 | 检测到 HDR 系列照片 |
| 相似场景 | AI 检测到场景相似度 > 80% 的照片 |
| 相似构图 | AI 检测到构图高度相似的照片 |
| 手动选择 | 用户主动选择多张照片 |

**用户故事：**

> 作为摄影爱好者，我希望系统能自动将连拍照片分组，以便从每组中挑选最好的。

> 作为用户，我希望手动将旅行中的多张照片创建为堆叠，以便保持相册整洁。

**验收标准：**

```gherkin
Scenario: 自动堆叠
  Given 用户上传了 10 张连拍照片（拍摄时间在 2 秒内）
  When 上传完成并经过 AI 引擎分析
  Then 系统自动将这 10 张照片创建为一个堆叠
  And 堆叠默认折叠，只显示封面
  And 用户点击堆叠可展开查看所有照片

Scenario: 手动堆叠
  Given 用户在相册中选中 5 张不同场景的照片
  When 用户右键选择"创建堆叠"
  Then 这 5 张照片被合并为一个堆叠
  And 用户可以设置堆叠封面
  And 用户可以随时拆分堆叠为独立照片
```

### 5.5.5 归档 Archive

| 功能 | 描述 | 优先级 |
|------|------|:------:|
| 归档照片 | 将照片从主时间线隐藏到归档 | P1 |
| 归档相册 | 将整个相册归档 | P1 |
| 取消归档 | 将归档照片恢复到主时间线 | P1 |
| 归档搜索 | 在归档内容中搜索照片 | P1 |
| 归档统计 | 显示归档照片数量、存储占用 | P1 |
| 自动归档规则 | 基于规则自动归档（如"1 年未查看的照片"） | P2 |
| 归档提醒 | 归档照片仍可被搜索和访问 | P1 |

**归档与删除的区别：**

| 操作 | 语义 | 数据状态 | 可恢复性 |
|------|------|---------|---------:|
| 归档 | 暂时不需要，但不想删除 | 保留在系统中 | 可随时取消归档 |
| 删除 | 不再需要 | 进入回收站 | 可在保留期内恢复 |
| 永久删除 | 彻底不需要 | 从系统移除 | 不可恢复 |

**用户故事：**

> 作为用户，我希望将旧照片归档，以便主时间线保持整洁但仍能访问这些照片。

> 作为用户，我希望设置自动归档规则（如"1 年未查看的照片自动归档"），以便系统自动整理。

**验收标准：**

```gherkin
Scenario: 归档照片
  Given 用户在主时间线中看到 100 张旧照片
  When 用户选择这些照片并点击"归档"
  Then 这些照片从主时间线消失
  And 照片被移动到归档区域
  And 用户可以在"归档"视图中查看这些照片
  And 归档照片仍可被搜索到

Scenario: 自动归档规则
  Given 管理员设置了"1 年未查看的照片自动归档"规则
  When 系统检测到有照片超过 1 年未查看
  Then 这些照片自动被归档
  And 用户收到归档通知
  And 用户可以在归档规则中取消自动归档
```

### 5.5.6 文件夹视图

| 功能 | 描述 | 优先级 |
|------|------|:------:|
| 文件夹浏览 | 按文件系统目录结构浏览照片 | P1 |
| 文件夹导航 | 面包屑导航（面包屑） | P1 |
| 文件夹操作 | 在文件夹中创建子文件夹、移动照片 | P1 |
| 文件夹上传 | 直接上传到指定文件夹 | P1 |
| 文件夹同步 | 文件夹视图与相册视图同步 | P2 |
| 文件夹权限 | 设置文件夹访问权限 | P2 |
| 文件夹统计 | 显示文件夹内照片数量、大小 | P1 |

**文件夹视图与相册视图的区别：**

| 维度 | 文件夹视图 | 相册视图 |
|------|----------|---------|
| 组织方式 | 按文件系统目录 | 按逻辑相册 |
| 一张照片 | 可存在于多个文件夹 | 只能存在于一个相册 |
| 物理位置 | 反映实际存储路径 | 逻辑组织 |
| 用途 | 浏览已有文件夹结构 | 创建新的组织结构 |

**用户故事：**

> 作为用户，我希望按文件夹结构浏览照片，以便与本地文件系统保持一致。

> 作为用户，我希望直接上传到指定文件夹，而不是先上传再移动。

**验收标准：**

```gherkin
Scenario: 文件夹浏览
  Given 系统中存在按日期组织的文件夹结构（如"2025/01/15"）
  When 用户进入文件夹视图
  Then 系统显示与存储路径一致的文件夹层级
  And 用户可以点击文件夹进入子目录
  And 每个文件夹显示照片数量和总大小

Scenario: 文件夹上传
  Given 用户在文件夹视图中导航到"2025/01/15"
  When 用户选择 10 张照片并上传
  Then 照片直接存储到"2025/01/15"目录
  And 不需要后续移动操作
```

## 模块级用户故事

> 作为家庭用户，我希望创建家庭相册并按标签分类，同时将旧照片归档，以便保持主时间线整洁但仍能快速找到回忆。

> 作为摄影爱好者，我希望创建嵌套相册结构管理拍摄项目，使用堆叠功能整理连拍，并按地理位置层级标签组织，以便高效管理大量照片。

> 作为工作室负责人，我希望为不同项目创建相册，使用智能相册自动收集符合规则的照片，并设置相册封面以便展示。

## 模块级验收标准

```gherkin
Scenario: 完整组织与分类流程
  Given 用户上传了 100 张照片
  When AI 引擎完成分析并返回标签和人物信息
  Then 用户可以创建相册并将照片添加到相册
  And 用户可以为照片添加标签（包括 AI 建议的标签）
  And 用户可以收藏喜欢的照片
  And 用户可以将连拍创建为堆叠
  And 用户可以将旧照片归档
  And 用户可以在文件夹视图中按目录结构浏览

Scenario: 智能相册自动更新
  Given 用户创建了一个智能相册，规则为"标签包含'风景'"
  When 系统中有新照片被 AI 引擎标记了"风景"标签
  Then 该照片自动出现在智能相册中
  And 智能相册的统计信息实时更新
  And 用户不需要手动添加照片到智能相册
```

## 依赖关系

```
5.5 组织与分类
  ├── 依赖：5.1（用户与账户管理 — 相册归属用户）
  ├── 依赖：5.13（AI 引擎 — 智能分类、自动标签、人物识别由 AI 引擎提供）
  ├── 被依赖：5.6（搜索与检索 — 标签用于搜索索引）
  ├── 被依赖：5.7（浏览与展示 — 相册用于浏览展示）
  ├── 被依赖：5.9（媒体管理与生命周期 — 归档由生命周期模块管理）
  └── 被依赖：5.10（分享与协作 — 相册可被分享）
```

> **注意**：本模块不包含 AI 智能分类的具体实现（如人脸检测算法、场景识别模型）。这些能力统一由 [5.13 AI 引擎与智能服务](./5.13-AI引擎与智能服务.md) 模块提供，本模块作为 AI 能力的消费者。
