# 照片信息管理系统开发计划

## 一、项目概述

### 1.1 项目背景
基于GitHub PRD需求文档，开发一个功能完善的照片信息管理系统。该系统采用前后端分离架构，前端使用Node.js + Vite，后端使用Java开发。

### 1.2 项目目标
- 实现照片信息的完整生命周期管理（录入、存储、查询、编辑、删除）
- 提供安全高效的前后端数据交互
- 遵循软件工程最佳实践
- 交付可部署的完整系统

### 1.3 技术栈
**前端技术栈：**
- 运行环境：Node.js
- 构建工具：Vite
- 框架：Vue 3 + TypeScript
- UI组件库：Element Plus
- 状态管理：Pinia
- 路由：Vue Router
- HTTP客户端：Axios

**后端技术栈：**
- 语言：Java
- 框架：Spring Boot
- ORM：MyBatis Plus
- 数据库：MySQL
- 认证：JWT
- 构建工具：Maven

## 三、数据库设计

### 3.1 核心数据表

#### 用户表 (t_user)
```sql
- id: BIGINT (主键)
- username: VARCHAR(50) (用户名，唯一)
- password: VARCHAR(255) (密码，加密存储)
- email: VARCHAR(100) (邮箱，唯一)
- nickname: VARCHAR(50) (昵称)
- avatar: VARCHAR(255) (头像URL)
- role: VARCHAR(20) (角色：ADMIN/USER)
- status: TINYINT (状态：0-禁用，1-正常)
- created_at: DATETIME (创建时间)
- updated_at: DATETIME (更新时间)
- last_login_at: DATETIME (最后登录时间)
```

#### 照片表 (t_photo)
```sql
- id: BIGINT (主键)
- user_id: BIGINT (外键，关联用户)
- album_id: BIGINT (外键，关联相册，可为空)
- title: VARCHAR(200) (照片标题)
- description: TEXT (照片描述)
- file_path: VARCHAR(500) (原始文件路径)
- thumbnail_path: VARCHAR(500) (缩略图路径)
- file_size: BIGINT (文件大小，字节)
- file_type: VARCHAR(20) (文件类型)
- width: INT (图片宽度)
- height: INT (图片高度)
- shoot_time: DATETIME (拍摄时间，从EXIF提取)
- camera_model: VARCHAR(100) (相机型号)
- gps_latitude: DECIMAL(10,7) (GPS纬度)
- gps_longitude: DECIMAL(10,7) (GPS经度)
- is_favorite: TINYINT (是否收藏：0-否，1-是)
- is_deleted: TINYINT (是否删除：0-否，1-是)
- view_count: INT (浏览次数)
- created_at: DATETIME (创建时间)
- updated_at: DATETIME (更新时间)
```

#### 相册表 (t_album)
```sql
- id: BIGINT (主键)
- user_id: BIGINT (外键，关联用户)
- name: VARCHAR(100) (相册名称)
- description: TEXT (相册描述)
- cover_photo_id: BIGINT (封面照片ID)
- photo_count: INT (照片数量)
- is_public: TINYINT (是否公开：0-否，1-是)
- sort_order: INT (排序序号)
- created_at: DATETIME (创建时间)
- updated_at: DATETIME (更新时间)
```

#### 标签表 (t_tag)
```sql
- id: BIGINT (主键)
- user_id: BIGINT (外键，关联用户)
- name: VARCHAR(50) (标签名称)
- color: VARCHAR(20) (标签颜色)
- photo_count: INT (照片数量)
- created_at: DATETIME (创建时间)
```

#### 照片标签关联表 (t_photo_tag)
```sql
- id: BIGINT (主键)
- photo_id: BIGINT (外键，关联照片)
- tag_id: BIGINT (外键，关联标签)
- created_at: DATETIME (创建时间)
```

#### 照片元数据表 (t_photo_metadata)
```sql
- id: BIGINT (主键)
- photo_id: BIGINT (外键，关联照片)
- iso: INT (ISO感光度)
- aperture: VARCHAR(20) (光圈)
- shutter_speed: VARCHAR(20) (快门速度)
- focal_length: VARCHAR(20) (焦距)
- flash: TINYINT (是否使用闪光灯)
- white_balance: VARCHAR(20) (白平衡)
- exposure_mode: VARCHAR(20) (曝光模式)
- metering_mode: VARCHAR(20) (测光模式)
- created_at: DATETIME (创建时间)
```

#### 分享记录表 (t_share)
```sql
- id: BIGINT (主键)
- user_id: BIGINT (外键，关联用户)
- photo_id: BIGINT (外键，关联照片，可为空)
- album_id: BIGINT (外键，关联相册，可为空)
- share_code: VARCHAR(50) (分享码，唯一)
- password: VARCHAR(100) (访问密码，可为空)
- expire_at: DATETIME (过期时间)
- view_count: INT (浏览次数)
- is_active: TINYINT (是否有效：0-否，1-是)
- created_at: DATETIME (创建时间)
```

#### 操作日志表 (t_operation_log)
```sql
- id: BIGINT (主键)
- user_id: BIGINT (外键，关联用户)
- operation: VARCHAR(50) (操作类型)
- target_type: VARCHAR(50) (目标类型)
- target_id: BIGINT (目标ID)
- detail: TEXT (操作详情)
- ip_address: VARCHAR(50) (IP地址)
- created_at: DATETIME (创建时间)
```

## 四、API接口设计

### 4.1 RESTful API规范
- 基础路径：`/api/v1`
- 认证方式：JWT Token（请求头：Authorization: Bearer {token}）
- 响应格式：JSON

### 4.2 统一响应格式
```json
{
  "code": 200,
  "message": "操作成功",
  "data": {},
  "timestamp": 1234567890
}
```

### 4.3 主要API接口

#### 认证模块
```
POST   /api/v1/auth/register       - 用户注册
POST   /api/v1/auth/login          - 用户登录
POST   /api/v1/auth/logout         - 用户登出
POST   /api/v1/auth/refresh        - 刷新Token
GET    /api/v1/auth/profile        - 获取用户信息
PUT    /api/v1/auth/profile        - 更新用户信息
PUT    /api/v1/auth/password       - 修改密码
```

#### 照片模块
```
POST   /api/v1/photos              - 上传照片
GET    /api/v1/photos              - 获取照片列表（支持分页、筛选）
GET    /api/v1/photos/{id}         - 获取照片详情
PUT    /api/v1/photos/{id}         - 更新照片信息
DELETE /api/v1/photos/{id}         - 删除照片（移入回收站）
DELETE /api/v1/photos/{id}/permanent - 永久删除照片
POST   /api/v1/photos/batch        - 批量操作
GET    /api/v1/photos/{id}/download - 下载照片
POST   /api/v1/photos/{id}/favorite - 收藏照片
DELETE /api/v1/photos/{id}/favorite - 取消收藏
```

#### 相册模块
```
POST   /api/v1/albums              - 创建相册
GET    /api/v1/albums              - 获取相册列表
GET    /api/v1/albums/{id}         - 获取相册详情
PUT    /api/v1/albums/{id}         - 更新相册信息
DELETE /api/v1/albums/{id}         - 删除相册
POST   /api/v1/albums/{id}/photos  - 添加照片到相册
DELETE /api/v1/albums/{id}/photos  - 从相册移除照片
```

#### 标签模块
```
POST   /api/v1/tags                - 创建标签
GET    /api/v1/tags                - 获取标签列表
PUT    /api/v1/tags/{id}           - 更新标签
DELETE /api/v1/tags/{id}           - 删除标签
POST   /api/v1/photos/{photoId}/tags - 为照片添加标签
DELETE /api/v1/photos/{photoId}/tags/{tagId} - 移除照片标签
```

#### 搜索模块
```
GET    /api/v1/search              - 综合搜索
GET    /api/v1/search/photos       - 搜索照片
GET    /api/v1/search/albums       - 搜索相册
```

#### 分享模块
```
POST   /api/v1/share/photo/{id}    - 分享照片
POST   /api/v1/share/album/{id}    - 分享相册
GET    /api/v1/share/{code}        - 访问分享内容
DELETE /api/v1/share/{code}        - 取消分享
```

#### 回收站模块
```
GET    /api/v1/trash               - 获取回收站照片列表
POST   /api/v1/trash/{id}/restore  - 恢复照片
DELETE /api/v1/trash/clear         - 清空回收站
```

#### 管理员模块
```
GET    /api/v1/admin/users         - 获取用户列表
PUT    /api/v1/admin/users/{id}/status - 更新用户状态
GET    /api/v1/admin/statistics    - 获取系统统计
GET    /api/v1/admin/logs          - 获取操作日志
```

## 八、部署方案

### 8.1 开发环境

- JDK：17+
- Node.js：18+
- MySQL：8.0+
- Redis：6.0+（可选）

### 8.2 生产环境
- 服务器：Linux（CentOS/Ubuntu）
- Web服务器：Nginx
- 应用服务器：Spring Boot内嵌Tomcat
- 数据库：MySQL 8.0
- 缓存：Redis（可选）
- 文件存储：本地文件系统/对象存储（OSS）

### 8.3 部署架构
```
用户 → Nginx（反向代理） → Spring Boot应用 → MySQL
                            ↓
                        文件存储
```

### 8.4 部署步骤

#### 后端部署
1. 安装JDK 17+
2. 安装MySQL 8.0+
3. 创建数据库并导入SQL脚本
4. 修改application-prod.yml配置
5. 打包：`mvn clean package -Dmaven.test.skip=true`
6. 运行：`java -jar photo-backend.jar --spring.profiles.active=prod`

#### 前端部署
1. 安装Node.js 18+
2. 安装依赖：`npm install`
3. 修改环境配置
4. 构建：`npm run build`
5. 将dist目录部署到Nginx

#### Nginx配置
```nginx
server {
    listen 80;
    server_name your-domain.com;

    # 前端静态文件
    location / {
        root /path/to/dist;
        try_files $uri $uri/ /index.html;
    }

    # 后端API代理
    location /api {
        proxy_pass http://localhost:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # 文件上传大小限制
    client_max_body_size 50M;
}
```

## 十、风险评估与应对

### 10.1 技术风险
- **风险：** EXIF信息提取可能不完整或不准确
- **应对：** 使用成熟的EXIF解析库，添加异常处理，对无法提取的信息进行默认值处理

### 10.2 性能风险
- **风险：** 大量照片上传和浏览可能影响系统性能
- **应对：** 实现异步处理、缩略图预加载、分页加载、虚拟滚动等优化措施

### 10.3 存储风险
- **风险：** 照片文件占用大量存储空间
- **应对：** 实现照片压缩、定期清理回收站、支持对象存储扩展

### 10.4 安全风险
- **风险：** 用户隐私照片可能泄露
- **应对：** 实施严格的权限控制、数据加密、安全审计
